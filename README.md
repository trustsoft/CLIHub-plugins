# CLIHub plugins

Curated plugin feed for [CLIHub](https://github.com/trustsoft/CLIHub).

CLIHub reads the feed index from:

```text
https://raw.githubusercontent.com/trustsoft/CLIHub-plugins/main/index.json
```

The feed is intentionally separate from the CLIHub application repository: plugin updates can be
published without an application release, and plugin contributions do not run the application CI.

## What a plugin is

A plugin is a data-only descriptor (`plugin.json`) plus an optional `logo.png`. CLIHub does not load
DLLs or execute plugin code in-process; it launches the commands declared in the descriptor in the
user's terminal. Treat every descriptor as executable content and review it accordingly.

## Layout

```text
plugins/
  <plugin-id>/
    plugin.json
    logo.png          # optional
scripts/
  build-index.mjs     # validates plugins and writes index.json
  package-plugin.ps1  # local packaging helper (Windows)
templates/
  plugin.json         # copy into plugins/<id>/plugin.json
reserved-ids.json     # CLIHub built-in ids that a feed plugin must not use
index.json            # generated by the publish workflow
```

## Adding a plugin

Step-by-step guide (Russian): [docs/ADDING-A-PLUGIN.md](docs/ADDING-A-PLUGIN.md).

1. Copy `templates/plugin.json` to `plugins/<plugin-id>/plugin.json`.
2. Set `id` to the folder name, fill in `name`, `description`, `version`, `publisher`, `homepage`,
   `minAppVersion`, and the command set.
3. Add `logo.png` if you have one.
4. Build the package locally:

   ```powershell
   pwsh scripts/package-plugin.ps1 <plugin-id>
   ```

5. Validate:

   ```powershell
   node scripts/build-index.mjs --check
   ```

6. Open a pull request. CI validates the descriptor, packages the plugin, publishes an immutable
   GitHub Release, and updates `index.json`.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the descriptor contract and review rules.

## Index schema

```jsonc
{
  "schemaVersion": 1,
  "lastUpdated": "2026-11-05T00:00:00Z",
  "plugins": [
    {
      "id": "my-agent",
      "name": "My Agent",
      "description": "Short description",
      "version": "1.0.0",
      "schemaVersion": 1,
      "minAppVersion": "0.0.0",
      "publisher": "Publisher",
      "homepage": "https://example.com/my-agent",
      "packageUrl": "https://github.com/trustsoft/CLIHub-plugins/releases/download/my-agent-1.0.0/my-agent-1.0.0.clihub-plugin.zip",
      "sha256": "<sha256 of the package zip>",
      "releaseNotesUrl": "https://example.com/my-agent/releases/1.0.0",
      "signature": null,
      "contentHash": "<feed-internal descriptor+logo hash>"
    }
  ]
}
```

- `signature` is reserved for future index signing; it is always `null` today.
- `contentHash` is feed-internal: it lets the publisher detect a changed descriptor without a version
  bump. CLIHub ignores unknown fields.
- `minAppVersion` and `releaseNotesUrl` are read from `plugin.json` by the feed builder; CLIHub ignores
  them in the descriptor.

## Versioning and immutability

- Each published version is a GitHub Release tagged `<id>-<version>` with an immutable package asset.
- A version is never overwritten. To change a descriptor, bump `version` and open a PR.
- The index always points at the latest version of each plugin. Removed plugin folders disappear from
  the index; their releases remain available for rollback.

## Reserved ids

`reserved-ids.json` lists CLIHub built-in agent ids. A feed plugin cannot use them: the application
rejects reserved ids at install time and filters them from the browse list. Update this list when a
new built-in agent ships in CLIHub.

## Package format

`<id>-<version>.clihub-plugin.zip` with exactly one top-level directory:

```text
<id>/
  plugin.json
  logo.png        # optional
```

No other files. CLIHub also enforces its own archive limits (10 MB / 100 files) and rejects zip-slip
paths, symlinks, and absolute paths.
